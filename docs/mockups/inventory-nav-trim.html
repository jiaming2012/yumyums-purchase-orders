Inventory Navigation Experiment

Seven tabs is past what a 480px pill bar can carry: on the phone the first label already wraps to two lines and the bar reads as a wall of words. The question is not "how do we fit seven" but "which of these are really peers". Tap the tabs in each phone below; they are live.

Two audiences, one bar

Stock and Receipts are the crew's daily loop. Recipes, Trends and Cost are the owner's weekly analysis. Setup is configuration. The bar treats all three as equals, so the crew scrolls past five tabs they never use.

BI already exists, empty

The HQ launcher has a "Business Intelligence: Sales and cost trends" tile marked Soon. Trends and Cost are literally that description, and they are already permission-gated the way an owner-only tool should be.

Menu is a view, not a tool

Every Menu card taps through to Recipes, and Recipes already ends with a read-only "Menu item summary". Those are the same thing seen from two ends.

Recommendation

Ship the hybrid: A's split, C's shape, in both Inventory and BI. B stays on the shelf.

Morning: ship A alone. WO-1 (the A trim inside the tab bar) shipped to dev the same day, so what owners see now is a six-tab bar and crew see four. The evening revision replaces that bar with a hub rather than trimming it further: the remaining problem is not width, it is that a bar shows names and a hub shows state. The hub taxes the two daily tasks one tap each, and pays it back with "10 to review" and "2 below par" on the first screen. B is still worth doing only when someone actually walks Stock → Order several times a week.

Inventory hub (frontend card). inventory.html opens on four rows — Receipts, Stock, Recipes, Setup — each with a live badge; every section becomes a full page with a back link to the hub; the tab bar goes away. No hash opens the hub, #tab=N still opens a section directly, slot ids stay. Granted owners see Trends and Food cost as rows 5 and 6 until the BI card lands.

New bi.html opens on a hub with Trends and Food cost; renderTrends / renderCost lift verbatim; the BI tile on the launcher goes active; the inventory-trends / inventory-cost grants become one BI app grant (db.go seed, RequirePermission, jwtbridge); states-trends / states-cost specs re-point at bi.html; build-sw.js precache 46 → 47; night-crew.toml gains a bi.html entry.
  3. Badges use existing calls (purchases list, sync-receipts/status, stock levels, recipes/drift, trends, cost). A single hub-summary endpoint is an optimisation to take later if landing feels slow, not a prerequisite.
  4. State table rows the hub adds: zero pending → no badge; status call failed → "Status unavailable" subtitle, row still tappable; loading → badge skeleton; offline → last-known badge with the sync subtitle saying so. Blank rows are defects.
  5. Done already (WO-1, 2026-09-29): Purchases renamed Receipts with the pending count as a corner badge; Sync / Deep sync / Retry parse collapsed into Sync Receipts + More; Menu folded into Recipes › By dish; Purchase Orders link dropped from Setup; legacy #tab=3 remapped.
