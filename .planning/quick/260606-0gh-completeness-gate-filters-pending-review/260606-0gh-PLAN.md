<objective>
Fix the completeness gate so the period_summary endpoint filters pending_purchases by the receipt's business date (event_date) rather than the worker's ingestion timestamp (created_at). Today, a late-discovered May 29 transaction lands in pending_purchases with event_date='2026-05-29' and created_at='2026-06-02'; a sales-processor query for May 25–31 currently misses it because the WHERE clause uses created_at, so ready returns true when it should be false and $391 of food cost silently drops out of weekly COGS.

Purpose: Make the gate's filter match what the receipt physically represents (when the purchase happened), with a safe fallback to created_at for rows where the worker bailed before extracting event_date.

Output: One query change in handler.go (WHERE + ORDER BY + comment), one new test helper, one modification to the existing no-attachment test, and four new event_date × created_at axis tests. No schema change.
</objective>
