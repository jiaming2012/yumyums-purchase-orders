<objective>
Fix the over-aggressive `bankTxIDExists` short-circuit in the Mercury receipt worker so that pending rows created with `reason='no_attachment_on_bank_tx'` get reprocessed when the user later uploads a receipt to that Mercury transaction. Also surface the `cached` count on the FE sync chip.

Purpose: Today, the receipt worker treats *any* row in `purchase_events` OR `pending_purchases` as "already ingested" and skips. When a tx first appears with no attachment, HQ writes a `no_attachment_on_bank_tx` pending row. Later, the user uploads the receipt in Mercury and re-syncs — the worker still sees the existing pending row and skips, so the attachment is never downloaded/parsed. The row stays at `$0.00` line items forever.

Output:
- `classifyExistingTx` replaces `bankTxIDExists` and returns `(kind, reason, err)` with `kind ∈ {"none","event","pending"}`.
- The `runIngestCycle` loop runs through the download/parse path when `kind=="pending" && reason=="no_attachment_on_bank_tx" && len(tx.Attachments) > 0`, marked as an `isUpgrade` iteration.
- Auto-create upgrade: DELETE the pending row + INSERT the purchase_event inside ONE `pool.Begin` transaction, preventing concurrent re-sync from inserting a duplicate event.
- Pending upgrade (parse/validate failure): UPDATE the existing pending row in place via new `updatePendingPurchase` helper — preserves `bank_tx_id` PK without ON CONFLICT skips.
- A `parseReceipt` package-level var seam lets the new tests inject a fake parser (smallest possible production-code change; no signature changes elsewhere).
- FE sync chip: `Last synced just now — N processed[, M auto-added][, K pending review][, C skipped]` — tail segments only appear when their count > 0.
</objective>

           // purchase_events wins. A confirmed pending row also counts as

               SELECT 'event' AS kind, COALESCE(reason,'') AS reason

               UNION ALL

                  AND discarded_at IS NULL
               LIMIT 1`, bankTxID).Scan(&kind, &reason)

               return "none", "", nil
           }
           if err != nil {
               return "", "", fmt.Errorf("classifyExistingTx: %w", err)

           return kind, reason, nil
