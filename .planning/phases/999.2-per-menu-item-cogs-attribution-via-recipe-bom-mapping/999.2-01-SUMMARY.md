## Decisions Made
- **Alert indirection wired at Plan 01, not Plan 04** — alertEnqueuer interface + alertSink var added now so Plan 04's drift scheduler dispatches via `alertSink.Enqueue(...)` with a test-overridable indirection. Avoids post-hoc refactor of an already-shipped scheduler.
- **Multi-env-var DB URL precedence** — helpers_test.go honors `DB_TEST_URL` first (existing project Taskfile convention via `backend/internal/inventory/period_summary_test.go`) and falls back to `TEST_DATABASE_URL` / `DATABASE_URL` per plan spec. Ensures tests pick up the existing dev env without re-export and tolerate CI alternates.
- **ID columns returned via `::text` cast in RETURNING** — pgx v5 scans UUID columns into pgtype.UUID by default; using `id::text` makes the Scan target a plain `string` to match the repository return signatures without pgtype dance.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Env var precedence for DB_TEST_URL**
- **Found during:** Task 2 (helpers_test.go authoring)
- **Issue:** Plan spec says `TEST_DATABASE_URL` or `DATABASE_URL`, but the project's existing test convention (Taskfile var, `internal/inventory/period_summary_test.go`) uses `DB_TEST_URL`. Following the plan literally would have caused all tests to skip silently in the existing dev environment.
- **Fix:** helpers_test.go checks `DB_TEST_URL` first, then `TEST_DATABASE_URL`, then `DATABASE_URL`. All three trigger the same connection path; the codebase's existing setting is honored without requiring re-export. Tests verified passing under `DB_TEST_URL=postgres://yumyums:yumyums@100.70.200.55:5433/hq_test?sslmode=disable`.
- **Files modified:** backend/internal/recipes/helpers_test.go
- **Verification:** All 8 TestRepository_* tests pass; helper's Skip path is reachable when none of the three are set.
- **Committed in:** 3d9362c

**2. [Rule 1 — Bug] pgx UUID Scan into string**
- **Found during:** Task 2 (initial test run prior to commit)
- **Issue:** Returning `RETURNING id` with id of type UUID scanned into a plain `string` variable would fail at runtime under pgx v5 (default scanner produces `pgtype.UUID`, not string).
- **Fix:** All INSERT RETURNING + UPDATE RETURNING + helper inserts use `RETURNING id::text` (or `purchase_item_id::text`) so the Scan target is a plain Go string. Matches the existing pattern in `internal/inventory/period_summary_test.go` (which uses `RETURNING id::text` for the same reason).
- **Files modified:** backend/internal/recipes/repository.go, backend/internal/recipes/helpers_test.go
- **Verification:** All 8 tests pass; UPDATE RETURNING returns the purchase_item_id as a string that matches `seedPurchaseItem()`'s return value (used in TestRepository_UpdateRecipeUsagePct_ReturnsNewSum).
- **Committed in:** 3d9362c (caught and fixed before commit)
