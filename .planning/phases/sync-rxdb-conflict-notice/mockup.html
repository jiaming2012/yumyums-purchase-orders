Card sync-rxdb-conflict-notice — what a crew member sees when their offline answer loses to master-wins, and how they get it back.

RxDB's default conflict handler is unconditional master-wins, verified at W2 (proof-lww.js): the later local write is discarded, the earlier server write survives, no clock participates, and error$ emits nothing. The one signal that fires is conflict$, which carries the whole discarded document. Every plate below is drawn from what that event actually contains — see UI-SPEC.md §"What conflict$ gives you" for the verbatim evidence and the limits.

The counting rule, stated once — every plate below obeys it. Three figures, and they are not the same figure.

1 · What happened — the banner headline counts recoverable answers overwritten in the window, across the whole sheet. A group's count chip is the same figure for that group. What has been done to a row never changes this number: restored, kept-theirs, failed and in-flight rows are all still counted, because the record still exists and the crew member can still act on it (Undo, Retry). It drops only when a record leaves the sheet — Dismiss, or ageing out of the retention window. Rows never leave on Restore or Keep, so Undo always survives — that part of the original design is unchanged and is what A-1 unbundled the banner from.

2 · What is left (A-1, new) — a second banner line counts rows still to review. A row is reviewed once it has been restored, kept or dismissed. An untouched row is still to review; a failed restore is still to review, not handled — there is unfinished business there; an in-flight restore has not landed yet, so it is too. When nothing has been handled the line reads “N still to review”; when some has, “N still to review · M handled”; when all has, “All N reviewed”.

3 · What we could not identify — counted separately and never folded into either figure above: its own banner line and a +N appended to the group's chip, so chip base + +N = rows drawn and the headline stays literally true as a number of answers.

And one rule about the batch button (A-2): Restore all N of mine acts only on rows still to review. It never re-writes a row the crew member already handled — a batch tap must not silently reverse a deliberate Keep theirs. So its N is figure 2 for that group, not figure 1.

what this design cannot do

Not a state — the honest boundary of the mechanism, here so the sign-off is given with it in view.

Three things no UI can fix

1. If nothing was subscribed, nothing is ever known. conflict$ is a plain RxJS Subject — no replay, no buffer. Subscribe where the replication is constructed or the event is gone. RxDB persists nothing about a resolved conflict, so the app must write the discarded value to durable local storage the instant the event arrives, or a reload loses the thing this whole screen exists to recover. Every plate above assumes that record exists. Where it lives is the UI card's call, not this mockup's.

2. Only the leader tab sees it. waitForLeadership defaults to true in a browser, so one tab replicates and the others follow — and only that tab's conflict$ fires. Two HQ tabs open, the wrong one closes, and the notice never appears. The banner must therefore read from the shared local record, not from a live subscription.

3. “Dana M., 6:12 PM” is only as real as the row. conflict$ carries no author and no timestamp of its own — every attribution above comes from fields on the document. That schema belongs to sync-rxdb-schema-and-replication; this mockup states a requirement on it and does not decide it. AMENDMENT A-2 hardens that requirement. This used to read “degrade to someone else if the schema doesn't carry who-and-when”. It no longer may: the batch confirm's whole job is to say exactly what is being overridden, and “you are overwriting someone” is not adequate on a food-safety record. A crew member deciding whether to replace a walk-in cooler reading needs to know whose reading and when. Who-and-when is therefore a required output of the schema card, not an option it may decline — and if it is declined, the confirm plate above cannot be built as drawn.
