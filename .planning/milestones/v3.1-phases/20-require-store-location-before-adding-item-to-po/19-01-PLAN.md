# Plan 19-01: Block unlocated items from PO and group picker by store location

## Goal

Prevent items without `store_location` from being added to a PO. Redesign the item picker to group items by store location, with unassigned items shown at the bottom with a "Set location in Setup" link instead of an "+ Add" button.

## Context Decisions

- D-01: Block at add-to-PO (not at approval)
- D-02: Location set via Inventory Setup (not inline in picker)
- D-03: Item picker grouped by store_location
- D-05: Existing null items appear under "Unassigned"

## Tasks

### Task 1: Block addItemToPO for items without store_location

File: `purchasing.html`, function `addItemToPO()` (~line 835)

Before adding the item to the PO, check:
```javascript
if (!catalogItem.store_location) {
  showToast('Set a store location in Inventory Setup before adding to PO');
  return;
}
```

This is a safety net — the picker UI (Task 2) will prevent the user from reaching this code for unlocated items, but the guard protects against edge cases.

### Task 2: Group item picker by store_location

File: `purchasing.html`, function `renderPickerList()` (~line 907)

Current: flat list of items filtered by search query.
New: group items by `store_location`, sorted alphabetically. "Unassigned" group at the bottom.

For each group:
- Render a sticky header: `<div class="picker-group-header">Giant</div>`
- Under the header, render item rows as before

For items in the "Unassigned" group:
- Instead of `<button>+ Add</button>`, show `<span style="color:var(--info-tx);font-size:12px">Set location in Setup</span>`
- The row is not clickable / no add action

Add CSS for `.picker-group-header`:
```css
.picker-group-header{padding:8px 16px;font-size:12px;font-weight:600;text-transform:uppercase;letter-spacing:0.5px;color:var(--mut);background:var(--bg);position:sticky;top:0}
```

### Task 3: Regression tests

Add tests to `tests/purchasing.spec.js` (or workflows spec if purchasing tests don't exist):

1. **Block test:** Create an item without store_location via API, open picker, verify no "+ Add" button for that item
2. **Group test:** Create items with different store_locations, open picker, verify group headers appear
3. **Allow test:** Create an item WITH store_location, open picker, verify "+ Add" button works

## Verification

- [ ] Item without store_location shows "Set location in Setup" in picker (no Add button)
- [ ] Item with store_location shows normal "+ Add" button
- [ ] Items grouped by store_location with headers
- [ ] "Unassigned" group appears at bottom
- [ ] Search still works within groups
