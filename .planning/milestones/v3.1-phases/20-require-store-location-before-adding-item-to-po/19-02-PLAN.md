# Plan 19-02: Group Inventory Setup items by Category + Store Location

## Goal

Redesign the Inventory > Setup tab to group items by `(Category, Store Location)` instead of category alone. Each group header displays as "Category, Store Location" — e.g., "Bread, Giant" or "Proteins, Restaurant Depot". Items with no store_location appear under "Category, Unassigned".

## Context Decisions

- D-04: Inventory Setup items grouped by Category + Store Location

## Tasks

### Task 1: Update item grouping in Setup tab

File: `inventory.html`, Setup tab rendering (find the function that renders the items list in the Setup/Items sub-tab)

Current: items grouped by `group_name` (category).
New: items grouped by `group_name + ', ' + (store_location || 'Unassigned')`.

Sort groups alphabetically by the composite key. Within each group, sort items alphabetically by description.

Group header format: `<div class="group-header">Proteins, Restaurant Depot</div>`

### Task 2: Ensure store_location is editable in Setup

Verify that the Setup tab allows editing `store_location` on individual items. If not, add an inline edit (tap to edit) or a field in the item detail/edit form.

Current state: `store_location` may only be editable via the shopping tab's "Add location" flow (`UpdateShoppingItemLocation`). Need to verify if Setup has its own edit path.

If no edit path exists in Setup:
- Add a `store_location` field to the item edit/create form in Setup
- Backend: ensure the item update endpoint accepts `store_location`

### Task 3: Regression tests

1. **Grouping test:** Verify items with different (category, location) pairs appear under separate group headers
2. **Unassigned test:** Items with null store_location appear under "Category, Unassigned"
3. **Edit test:** User can set store_location from Setup tab

## Verification

- [ ] Setup tab shows items grouped by "Category, Store Location"
- [ ] Null-location items show under "Category, Unassigned"
- [ ] Groups sorted alphabetically
- [ ] Items within groups sorted alphabetically
- [ ] User can edit store_location from Setup
- [ ] Changes to store_location persist on reload
