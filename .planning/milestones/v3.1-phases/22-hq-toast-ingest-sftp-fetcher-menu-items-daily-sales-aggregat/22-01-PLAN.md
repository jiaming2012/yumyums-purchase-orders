Create `backend/internal/db/migrations/0061_daily_menu_sales.sql` with exactly this content:

```sql
-- +goose Up
BEGIN;

CREATE TABLE daily_menu_sales (
  menu_item_id  UUID NOT NULL REFERENCES menu_items(id) ON DELETE CASCADE,
  business_date DATE NOT NULL,
  units_sold    INTEGER NOT NULL,
  gross_amount  NUMERIC(10,2) NOT NULL,
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (menu_item_id, business_date)
);

CREATE INDEX daily_menu_sales_business_date_idx ON daily_menu_sales(business_date DESC);

COMMIT;

-- +goose Down
BEGIN;
DROP TABLE IF EXISTS daily_menu_sales;
COMMIT;
```

Notes:
- Composite PK `(menu_item_id, business_date)` is the natural key — no surrogate UUID needed (no other table references a single sales row). Saves one column + one index.
- `units_sold INTEGER` (D-06 excludes voided lines entirely; integer suffices for aggregate qty per day).
- `gross_amount NUMERIC(10,2)` matches the project convention from `purchase_events.total` (line 39 of 0024_inventory.sql).
- `updated_at` is bumped on every upsert (last-pull wins per D-05) by the ingest layer; the DEFAULT covers initial INSERTs.
- ON DELETE CASCADE means dropping a menu_item cleans up its sales rows (a manual operator action — the worker never deletes menu_items).
