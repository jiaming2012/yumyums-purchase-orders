# Phase 22.1 Plan 02: Spaces-first sync + Spaces-only ingest Summary

**Splits the Toast pipeline at the Spaces boundary: `SyncDate` is the only SFTP toucher (cache→Spaces atomic write), and `RunIngest` reads exclusively from Spaces. D-04 sync/ingest separation, D-13 cache-is-forensic, and D-14 cache ⊆ Spaces invariant all encoded.**

## Accomplishments

- New `backend/internal/toast/sync.go` exports `SyncDate(ctx, cfg, date) (bool, error)` and the `ErrSFTPMiss` sentinel
- `SyncDate` writes the local forensic cache file FIRST, then uploads to DO Spaces — on PutObject failure, `os.Remove(cachePath)` runs so the `cache ⊆ Spaces` invariant (D-14) is preserved
- Sidecar `.meta.json` written best-effort to both cache and Spaces with `source: "sftp"` (D-03); marshal/write/upload failures are logged but never block the CSV success path
- Clean SFTP miss AND 3-retry dial exhaustion both return `ErrSFTPMiss` — Plan 04's worker will log the single D-05 INFO line on this signal
- `dialWithRetry` moved verbatim from `ingest.go` to `sync.go` with the Phase 22 D-10 5s/15s/30s backoff schedule preserved; log prefix changed `toast ingest:` → `toast sync:` to match the new home
- `RunIngest` rewritten to read CSVs from `cfg.SpacesClient.GetObject` keyed by `SpacesCSVKey(dateDir)` — `os.ReadFile(cfg.SFTPKeyPath)`, `dialWithRetry`, and `client.Download` are entirely gone from `ingest.go`
- `s3types.NoSuchKey` via `errors.As` is the canonical Spaces-404 path → graceful per-date skip; other Spaces errors logged per-date but don't abort the cycle (Pattern 3 isolation)
- Pre-flight `SpacesClient`/`SpacesBucket` nil check returns a systemic error so Plan 04's worker can record it on the consecutive-failure counter
- Phase 22 D-05/D-07 SQL contract preserved verbatim in `upsertDayInTx` and `isColdStart` — no schema/SQL changes
- `RunIngest` signature unchanged: `worker.runCycle` and `cmd/sync-toast` (not yet present in this plan but expected by Plans 04/06) compile without edits
- `go build ./...`, `go vet ./internal/toast/...`, and `go test ./internal/toast/... -count=1` all green at every commit boundary

## Decisions Made

- **`dialWithRetry` move folded into Task 1 commit.** The plan's Task 1 verify runs `go build ./internal/toast/...`. If sync.go added `dialWithRetry` while ingest.go still had it, the package would fail with "redeclared". The clean interpretation of "move" is a single coherent operation (delete-from-source + add-to-destination), so deleting `dialWithRetry` from ingest.go happened in Task 1's commit. `RunIngest` still references `dialWithRetry` after Task 1 (resolves to the sync.go-defined function in the same package) — the SFTP→Spaces switch then happens cleanly in Task 2. Documented as Rule 3 (auto-fix blocking issue) under Deviations below.
- **`strings` import dropped from sync.go.** The plan's example code carried a `_ = strings.TrimSpace` guard; the plan NOTE explicitly invited dropping it if `strings` was otherwise unused. The body needed no `strings` symbol, so the import and guard line are both omitted; `goimports -w` confirmed clean.
- **Sidecar uses `Bytes()` from Plan 01's `MetaSidecar`.** Plan 01 (per its summary) deliberately named the helper `Bytes()` rather than `MarshalJSON()` to avoid overriding the json.Marshaler contract. sync.go uses `meta.Bytes()` straight; no JSON method-name fight.
