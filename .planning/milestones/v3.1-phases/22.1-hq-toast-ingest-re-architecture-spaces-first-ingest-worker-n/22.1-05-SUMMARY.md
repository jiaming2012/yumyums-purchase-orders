## Decisions Made

- **`envOrDefault` placement.** Plan instructed "append this helper after main() closes" — done verbatim. Could have lived nearer the top of the file but the plan's choice keeps the boot-sequence body readable as one continuous block.
- **Used `feat` for Task 2's commit type (not `refactor`).** While Task 2 rewrites an existing file's structure, the *behavioral* change — sync-toast now reads from Spaces, validates 5 new env vars, and requires the DO Spaces credentials at startup — is a new feature for the CLI consumer. The exit-code contract is preserved but the env-var contract grew (5 new required vars).
- **Used `feat` for Task 1's commit type (not `refactor`).** Task 1 introduces a new behavior — the toast worker can now actually process data (was previously dormant per Plan 04's graceful-skip guard). The wiring change activates a feature, not just refactors structure.
- **CLI keeps `LoadConfigFromEnv` (D-12 SFTP key path required even though no SFTP dial).** This was explicitly called out in the plan's `<behavior>` block under "single env contract". Operator running sync-toast must have the same boot guards as the server — keeps the CLI from drifting from server semantics. T-22.1-22 mitigation.
- **Five-env-var validation inline in CLI, not factored into a helper.** A `LoadSpacesConfigFromEnv()` helper would be cleaner DRY (used in cmd/sync-toast AND cmd/migrate-toast-archive AND cmd/server's inline validation at lines 254-269). But Plan 03's cmd/migrate-toast-archive already has its own inline validation (per its summary), and the plan-as-written did not request a refactor of cmd/server's inline path. Two-place duplication is preferable to a one-time refactor that would touch unrelated files this plan doesn't own.

## User Setup Required

None for cmd/server. The five `DO_SPACES_*` env vars are already required by photos/receipt pipelines — operators running the full server have these set. If they are unset, the toast worker now follows Plan 04's graceful-skip path (logs WARNING, ingest disabled, server continues).

**One operator-facing change for cmd/sync-toast:** The CLI now requires `DO_SPACES_KEY`, `DO_SPACES_SECRET`, `DO_SPACES_ENDPOINT`, `DO_SPACES_REGION`, `DO_SPACES_BUCKET` to be set. Pre-Phase-22.1, sync-toast only needed `DB_URL` + `TOAST_SFTP_*` env vars. Documented in the package doc comment ("Env (shares LoadConfigFromEnv with cmd/server)") and the five-var error message provides clear feedback if any are missing.

**Optional override:** `TOAST_CACHE_DIR` (default `backend/cache/toast`) — operator can redirect the forensic cache (e.g., to a larger disk or an SSD scratch path). D-13 says cache is read-only-for-humans (ingest never reads from it), so the override is safe to flip at any time.
