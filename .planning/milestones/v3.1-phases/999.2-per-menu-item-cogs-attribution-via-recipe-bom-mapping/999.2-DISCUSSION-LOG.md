## Recipes tab UX & placement

### Where should the Recipes UI live in inventory.html?

| Option | Description | Selected |
|--------|-------------|----------|

### How should an ingredient row display + allow editing?

| Option | Description | Selected |

### When a Toast menu item disappears (removed/renamed/no longer sells), what happens to its recipes?

| Option | Description | Selected |

## Cost reference price

### For a given week, which purchase prices feed ingredient_cost_per_unit?

| Option | Description | Selected |
|--------|-------------|----------|

## menu-cogs endpoint contract

### Who's the truth source for units_sold per menu item?

| Option | Description | Selected |
|--------|-------------|----------|
| sales-processor sends units_sold in POST body | Stateless; testable without Toast | |
| HQ reads units_sold from daily_menu_sales | Single truth source | (overridden — see notes) |
| Hybrid with divergence_pct | Overkill for v1 | |

**User's response:** Override — free-text: "HQ should become the source of truth. sales-processor would just fetch info from HQ to place into report" → **D-13**

This reshaped the entire contract from POST-with-body to GET-with-query-params.

### HTTP method + path — POST as sketched or GET to mirror Phase 21?

| Option | Description | Selected |

**User's choice:** GET → **D-14**
