# Milestone v3.1: Toast Integration & COGS Pipeline

**Status:** ✅ SHIPPED 2026-06-05
**Phases:** 18, 20, 21, 22, 22.1, 999.2
**Total Plans:** 24

## Overview

v3.1 connects HQ's purchase pipeline (v1.1) to the sales floor: HQ becomes a self-contained Toast SFTP consumer, ships a service-token COGS endpoint to sales-processor for weekly payroll gating, and lays a recipe/BOM mapping so per-menu-item COGS can be attributed. The accompanying Recipes tab UI lets the owner allocate ingredients to dishes with a 5%-snap slider and surfaces weekly drift signals when allocations decay. Phase 18's photo-on-onboarding work and Phase 20's store-location enforcement ride along as smaller PO/training polish.

### Phase 999.2: Per-menu-item COGS attribution via recipe/BOM mapping

**Goal:** Allocate ingredient cost from `purchase_line_items` to individual menu items so the weekly report can show "Jerked Chicken Sliders sold N units, ingredient cost $X". Builds on Phase 22's `menu_items` + `daily_menu_sales` ingest by adding a recipe/BOM table linking `purchase_items` → `menu_items` with a usage percentage per ingredient per dish.

**Scope:**
1. **DB migration** — `recipes` (id, menu_item_id FK, purchase_item_id FK, usage_pct NUMERIC(5,2), updated_at; unique on (menu_item_id, purchase_item_id))
2. **Per-ingredient view** — Recipes tab in `inventory.html` defaults to ingredient-first; week-spend sorting; 5%-snap slider with running total
3. **Sum constraint** — per `purchase_item_id`, `SUM(usage_pct)` cannot exceed 100. Save-time validation with named-sibling 422 envelope
4. **Weekly drift check** — 3 sections: unallocated > 10%, divergence > 20%, zero-sales. Cliq alert on drift; banner on Recipes tab
5. **HQ endpoint** — `GET /api/v1/inventory/menu-cogs` (service-token, peer of Phase 21). D-18 contract mirrors period-summary byte-for-byte
6. **sales-processor consumer** — POSTs `menu_items+units_sold` per week → renders "COGS by Menu Item" rows in `WeeklySummary.Show()`. **(HANDED OFF via 999.2-SALES-PROCESSOR-CONTRACT.md)**

**Depends on:** Phase 22 (menu_items pipeline) and Phase 21 (service-token auth pattern)

## Milestone Summary

**Decimal/inserted Phases:**
- Phase 22.1 (inserted after Phase 22 — Spaces-first re-architecture revealed during Phase 22 verification; both closed together)
- Phase 999.2 (originally backlog; pulled forward and shipped as v3.1 capstone)

**Key Decisions:**
- HQ becomes a peer Toast SFTP consumer (not dependent on sales-processor). Deployment topology stays decoupled.
- DO Spaces as source of truth for Toast historical data — SFTP purges faster than the backfill window.
- Recipes use rough usage % (not per-unit BOM). Setup cost ~1 evening vs ~1 week; reconciliation residual catches drift weekly.
- Sum-constraint server-side enforcement is bypass-resistant (D-03) — 422 even if UI sum-check is skipped.
- Snap invariant: usage_pct must be a multiple of 5 (enforced in handler AND DB CHECK).
- Menu cards on Menu tab → Recipes summary cross-link (extension during human-verify of Phase 999.2-05).

**Issues Resolved:**
- Picker `since=` integer → YYYY-MM-DD format mismatch (Phase 999.2-05 fix)
- Stale Setup tab IDs in 30+ tests after Recipes tab insertion (Phase 999.2-05 migration)
- newItem hash routing hardcoded `hashTab='6'` for Setup (Phase 999.2-05 fix)

- Per-unit BOM precision — only when usage % stops being good enough
- Tab persistence on refresh (Phase 999.1) — parked, not in v3.1
