## How the three parked decisions are rendered (not fixed)

- **D-4 (attribution unresolvable).** The `unattributed` row is a **real,
  labelled row** on the by-campaign slice and is **never filtered out** — Σ rows
  = overview is the engine's keystone. It is toned (not hidden) so a manager can
  see the money belongs to no campaign, and it does not drill in, because it
  names no filterable entity. The overview states the same fact at **period
  scope** from `unattributed_redeemed` / `unattributed_revenue_cents`, and when
  the count is 0 it says so, because at that scope 0 is a stated fact.
- **D-5 (orphan-rate numerator).** The card renders the **server's**
  `orphan_rate`, `orphan_numerator`, `orphan_denominator` and
  `orphan_rate_basis` beside the 10% marker, so the marker is never a bare
  claim. **This file performs no orphan arithmetic** — it never divides.
  Changing what the rate counts is a PARK.
- **D-3 (`opened_at` zone).** `suggestion.basis` and `gap_seconds` are rendered
  **on the chip**. A `business_date` suggestion is toned as advisory, carries
  "same business date" and a sentence saying it is outside the 30-minute window,
  and is **not pre-filled** into the order field — only a `window` suggestion is.
