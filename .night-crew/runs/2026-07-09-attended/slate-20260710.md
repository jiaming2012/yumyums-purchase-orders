## Run mechanics (defined inline — first slate, nothing to inherit)

Standing rules for every card this run (this slate establishes the baseline future slates inherit by reference):

- **G1 — Draft-shape gate.** The PRD follows the signed exemplar structure: Objective · Operators & users · Requirements (with the WORKING/UNPROVEN/BROKEN legend) · Acceptance criteria (surface-anchored Given/When/Then) · Verification plan · status tally · Out of scope · Success metrics.
- **G2 — Traceability gate.** Every requirement points to a specific `okrs.md` KR; if it doesn't, it's cut (operator brief hard constraint).
- **G3 — Honest-status gate.** Every flow marked WORKING/UNPROVEN/BROKEN. **BROKEN only for *confirmed* breakage** (code inspection proves absent/stubbed); merely-suspect stays UNPROVEN with a confirm-absence step. No aspirational flows — each traces frontend → API → database.
- **G4 — Two-pass gate (non-negotiable).** First enumeration pass **and** an independent cross-check pass (angled at the blind spot named per track), with the recall note recorded. Single-pass recall came in at 85% on Operations — under the 90% KR; the cross-check is mandatory.
- **G6 — Adversarial review.** A **separate fresh subagent** reviews each drafted PRD against ONLY: the signed exemplar, this slate's card entry, and `okrs.md`. It checks G1–G4 pass, flags aspirational flows / untraceable requirements / vacuous-status marks. PRD is not accepted (roadmap row not flipped) until G6 passes or the gap is explicitly parked.

Depth reminder: these are **doc-drafting** cards — no worktrees, no app run, no DB, no E2E suite. The subagent reads app source + tests and writes one PRD file.
