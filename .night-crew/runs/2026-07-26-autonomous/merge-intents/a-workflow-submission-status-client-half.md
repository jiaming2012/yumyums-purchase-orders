## Card in one line

Card F1 (`overnight-20260725`) taught the **server** to write
`checklist_submissions.status = 'completed'` for a `requires_approval:false` submission.
`workflows.html` was never taught that word — it recognises only
`submitted` / `pending_approval` / `pending` / `approved`, so `'completed'` falls through
to the **else** branch and a submitted no-approval checklist comes back **fully editable,
unbadged, with a live `#submit-btn` and `fillState.readonly` false**. Two E2E specs are
knowingly RED on `dev` because of it. This card teaches the client the DB's vocabulary at
all seven call sites, adds the render-side test the suite never had, and lands the
`night-crew.toml` seam expansion.

## What must survive any merge

1. **`'completed'` is recognised as the terminal submitted state at every status call
   site.** Specifically the render gate `isSubmitted` in `renderRunner` (`:2093`), the
   `submittedBadge` in the list row (`:2067`), the `getProgress` snapshot gate (`:2411`),
   and the hydration gate (`:2453`). Dropping *any one* of these silently restores a
   different half of the bug: dropping `:2093` makes the checklist re-submittable, dropping
   `:2067` un-badges it in the list, dropping `:2411` mis-counts its progress, dropping
   `:2453` hydrates against the live template instead of the frozen snapshot.
2. **The optimistic write agrees with what the server actually stores** (`:2717`, `:2720`).
   The pre-fix code writes `'submitted'` / `'pending_approval'` — **neither value is ever
   persisted by the server**. The optimistic value must be the same string a reload would
   produce, or the pre-reload and post-reload renders disagree and the bug hides behind the
   optimistic value exactly as it did until now.
3. **Both tests in `tests/workflows.spec.js`.** The cherry-picked red-first `RUN-09b`
   (reload-and-reread, from `0b53d46`, kept verbatim) and the new render-assertion test. A
   triage sweep found **exactly two tests in the whole suite** that create a
   `requires_approval:false` template, submit it, and assert on the rendered result — and
   both were the two red ones. `GATE-01/03/06` pass **vacuously**: they assert submission is
   *blocked*, never that it *rendered*. Without the new test the repair ships with the same
   blind spot.
4. **The `night-crew.toml` seam expansion.** Both keys, all four spec tokens. This is the
   process fix; the code fix without it just re-arms the same trap for the next card that
   touches `workflows.html`.
