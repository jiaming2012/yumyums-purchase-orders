### Card 4 · `clock-offset-on-sync` — tamper-safe offline expiry

On every successful pull, capture `offset = serverNow − deviceNow` from the PostgREST
response's `Date` header (spike-proven source: 196 ms recovery under a 2-day skew; the
`now()` RPC fallback is not needed), store it beside the checkpoint, and run every offline
`expires_at` comparison as `deviceNow + offset < expires_at` (§5.1). Red-first: the naive
`deviceNow` comparison ACCEPTS a dead code under a fast clock; the adjusted check rejects
it. done_when: with the device clock ≥2 days fast, an expired code is still rejected
offline (E-KR4's pinning test). Footprint: rxdb replica. **PARK note (narrow):** none
