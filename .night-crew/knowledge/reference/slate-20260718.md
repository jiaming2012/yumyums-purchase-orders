### `editprop-convergence-cell-hardening` *(convergence-hardening, ~70–95m)*

Two bundled mechanisms, deliberately folded into one card at triage (F-A — "a small
coverage-extension worth folding into the same card"):

1. **Zero-flake under no-retry.** The two-device convergence cells run through `survivalCell`
   (`sync.spec.js:782`): device B enters an answer, the answer is gated provably-server-side by
   `waitFieldPersisted` (already removed the answer-persistence flake class), admin cuts the Decoy
   (SAVE_TEMPLATE op), then B must converge LIVE (`Decoy` count → 0 within `CONVERGE_TIMEOUT`
   =12000ms, `:746`) and again on CATCH-UP reopen. Under the shipped `retries:1` the suite is
   green (orchestrator 36/36 twice); under **no-retry** the `text answer converges` (`:849`) and
   `temperature answer converges` (`:862`) cells fail ~3/6 — residual two-device WS-timing race
   (reproduced on base `733fa16`, so pre-existing to W-6; a harness sensitivity, **not** a product
   defect). Chase these to zero-flake under no-retry: prefer a deterministic wait signal on B (await
   the SAVE_TEMPLATE op *applied*, not the visible re-render) over widening timeouts; add a `sync.js`
   applied-op test seam only if the spec genuinely cannot observe convergence otherwise. **Prove it**
   by repeat-running the two-device cells N× under no-retry and recording the pass streak in the WO
   record (a single green run is not proof of determinism — the 07-16 cycle-gate isolation-re-run
   discipline applies).
2. **Conflict-branch coverage extension.** The W-6 LWW-conflict test (`sync.spec.js:1192`) proves
   only `text`/textarea: a losing device (WS stubbed dead) that 409s must re-render the WINNING
   value from the 409 body. The other ~6 persisted types (checkbox, yes/no, temperature, sub-step,
   fail-note text+severity, fail-note photo-URL) ride the **same** `applyOp` conflict path
   (`sync.js`) but are untested there. Parameterize the conflict cell over those types — each a
   red→green cell asserting the losing device renders the winner's value, never its rejected one.

**Footprint:** workflow-engine convergence tests (`sync.spec.js`, `repro-cut-task.spec.js`,
`broadcast-rerender.spec.js`) + `sync.js` **iff** a test determinism seam is needed.
**Red-first:** the new conflict-type cells are red-first (fail on the untested path if it were
broken, green when asserted correct); the de-flake half is proven by the no-retry repeat-run streak,
not a red→green pair. → Delivery KR "convergence proof (no-retry hard gate)", Eng KR "convergence
matrix". **PARK trigger:** if zero-flake under no-retry demands a change **beyond** a test-scoped
`sync.js` determinism seam — a production-behavior change to the broadcast/apply path, or a new op
type — PARK with the specific residual (which cells, what plumbing) to DECISIONS-NEEDED; land the
conflict-coverage half regardless (it is independent of the de-flake investigation).
