#### A1 · `sync-replication-scope-per-checklist` — Wave 0, dispatched first

**Scope.** Give `startHQReplication` a pull filter so replication is scoped to the open checklist
instead of pulling four collections in full. Today `sync-rxdb/client.js:378` loops
`REPLICATED_COLLECTIONS` calling `replicateSupabase` with `pull: { batchSize: 50 }` and **no
selector, filter or query modifier** — verified in the tree at planning time. Two consequences:
(a) the RLS predicate is re-evaluated per row on every page, which is the entire arithmetic behind
Fork 1's ~23 s figure (20 pages × 50 rows × ~23 ms); (b) **unbounded phone storage** —
`submission_responses` grows forever and every device was to hold all of it.

**Also required:** re-measure the ~23 ms/row constant on production-like topology. It was measured
through Docker loopback NAT, which production does not have. The linear **shape** is structural;
the **constant** is not, and no card may rely on the specific number until it is re-taken.

**Why it goes first.** It gates `sync-hard-cutover`, and it establishes the substrate state A2 then
writes policies against. Ledger T-29 decision 105 is the standing rule it discharges — and per the
same decision's amendment (`architecture/C-2`, pending), the general principle is wider than
replication: **any** client-side fetch over a collection that can grow without bound should batch.

**Red-first (mandatory).** The red is a test asserting a device does **NOT** hold rows for a
checklist it never opened.

**Footprint.** `sync-rxdb/client.js` (pull selector), `sync-schema/collections.js` (only if the
scope needs a queryable key), `tests/sync-rxdb-client.spec.js`.

**PARK if:** scoping requires a schema change to the four replicated tables (that is A2's
substrate and a different card's semantics); or the re-measurement cannot be taken because the
substrate will not stand up — **report the number as untaken rather than reusing the Docker-NAT
figure.** A missing measurement is a finding, not a footnote.

#### A2 · `sync-rxdb-write-policies` — dispatched only after A1 merges

**Scope.** Make RxDB **push** replication possible at all. Today `sync-schema/sql/0003_rls_policies.sql`
has SELECT policies only — zero `WITH CHECK`, zero `FOR INSERT`, zero `FOR UPDATE` (grepped at
planning) — so every push is refused. Implement decision 111's per-table contract:

| Table | SELECT | INSERT/UPDATE |
|---|---|---|
| `checklist_templates` | unchanged: `hq_can_see_template(id)` | **DENY-ALL, deliberately.** Builder keeps the REST path. **Assert the refusal with a variant** — do not leave it as an absence. |
| `checklist_submissions` | unchanged | `WITH CHECK (public.hq_can_see_template(template_id))` — closes the lie `0003_rls_policies.sql:243` names by hand. |
| `submission_responses` | unchanged | `WITH CHECK (public.hq_can_see_field(field_id))`. **Field-scoped, never submission-scoped** — `submission_id` is nullable for offline drafts, and scoping by submission would leave the one collection that MUST sync unresolvable, silently. |
| `submission_rejections` | 🛑 **NEW** — `for select using (public.hq_can_see_field(field_id))` | **Approver-only:** new `public.hq_can_approve_template(tid)` = `EXISTS` an assignment with `assignment_role = 'approver'` **OR** the unconditional `roles && ARRAY['admin','superadmin']` arm. |

🛑 **Two spec lines that are decided, not discoveries.**
1. **Approvals must become readable.** `submission_rejections` is RLS-enabled with zero policies —
   deny-all both ways, asserted by variant V17. A device that can write a row it cannot read back
   breaks replication. The assignee whose field was rejected must read their own feedback.
2. **This is the FIRST place `assignment_role` is filtered on**, and it deliberately breaks a
   property recorded as "knowing, not accidental." Reads keep it untouched; only the approval
   `WITH CHECK` uses the new predicate. **Do not "tidy" this by making reads match.**

**Gate — an attack-variant suite, red-first**, extending the shipped 27-subtest
`backend/internal/sync/rowvisibility_rls_test.go` rather than opening a new file. Minimum variants,
each captured **refusing before the policy that refuses it is written**: push a submission claiming
a `template_id` you cannot see; push a response on a field you cannot see; push a template edit as
an assignee; write an approval as a plain assignee; write an approval as an approver (positive);
admin writes everything (positive). **Keep the `service_role` BYPASSRLS control and the population
floors** — a 200 alone proves nothing, and an empty table explains any green.

**🛑 Also fixes B-36 — this is the card's own gate, not scope creep.** `resolveSpikeConfig` turns
any `docker compose … port` failure into `t.Skip`, so `internal/sync` prints `ok` and exits 0 while
skipping the entire RLS suite. This card **doubles that suite's size**. Gate `t.Skip` on an explicit
`HQ_SYNC_SUBSTRATE_OPTIONAL=1` opt-out and `t.Fatal` otherwise. Until it lands, T-29 decision 108's
reporting rule applies to this card's own evidence: **cite `-run TestRowVisibilityRLS -v` output
showing subtests executed**, never the package `ok` line.

**Footprint.** `sync-schema/sql/0003_rls_policies.sql` (or a new `0004_write_policies.sql`),
`backend/internal/sync/rowvisibility_rls_test.go`, `backend/internal/sync` (the `resolveSpikeConfig`
skip path).

**PARK if:** a write predicate is needed beyond the four rows of decision 111's table (operator
