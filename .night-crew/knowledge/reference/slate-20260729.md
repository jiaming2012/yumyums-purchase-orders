## Wave 0

**Card A · `precache-manifest-from-head`** — PLANNED, HIGH, small.
Switch `build-sw.js` from `git ls-files` (reads the **index**) to `git ls-tree -r --name-only HEAD`
(reads the **commit**), so a staged-but-uncommitted file cannot enter the precache manifest. A
precached URL that 404s fails the *entire* SW install for every returning client, and
`task prod:deploy` ships the **committed** `sw.js` without regenerating it — the trigger path is
complete and was reproduced end-to-end at triage. Amends decision 58's literal text in service of
its intent (T-25 decision 67).
- **Red-first is the point:** stage a file, assert it is absent from the manifest.
- `tests/sw-manifest.spec.js` test 1 uses the same `git ls-files` — **it must move to `ls-tree` too**
  or it will keep agreeing with the bug.
- **Do NOT drop `GENERATED_BUT_SHIPPED`** — `version.json` is git-ignored but
  `backend/Dockerfile:33-44` regenerates it into the image *because* `sw.js` precaches it.
- Footprint: `build-sw.js`, `tests/sw-manifest.spec.js`, regenerated `sw.js`.
- **Estimate ~1h30m–2h** (basis: 07-27 Card A `pwa-cache-and-build-hygiene`, same class —
  50m impl + 41m G6 + 10m repair = 1h41m end-to-end).
- PARK trigger: if `ls-tree` turns out to exclude something the image genuinely ships beyond the
  allowlist — that is a Dockerfile question, not a globber question.

## Track A (backend-led)

**Card B · `workflow-queue-period-and-failnote-upsert`** — PLANNED, small/medium. Folds T-25
decision 71 (D-4 + D-5), plus two items added 2026-07-28.
1. **`submission_fail_notes` duplicates** — measured, not reasoned: same payload POSTed twice with
   one `idempotency_key` → identical submission id, `fail_note_rows=2`. No unique constraint
   (migration `0013`), bare insert at `repository.go:760-767` while the responses insert directly
   above carries `ON CONFLICT (submission_id, field_id) DO UPDATE`. An approver sees the note twice.
   Fix: matching `ON CONFLICT` + unique index.
2. **Cross-period stale queue entry** — `findQueuedSubmission` filters on `template_id` only, queue
   entries carry no period, nothing ages them out, so a persistently-failing server lets a stale key
   adopt a **later day's** submit. Fix: bound the lookup to the current period, age out stale
   entries.
3. **Make the durable falsehood true** — `workflows.html:1781` (**anchor re-checked 2026-07-28;
   was `:1694` before `bc8721e` moved it**) claims *"the server upserts only the fields present in
   each payload."* True for `submission_responses`, **false for `submission_fail_notes`** — item 1
   makes the sentence accurate rather than editing it away.
4. **"Pending sync" vocabulary collision** (new, 2026-07-28) — `sync.js:642` renders that exact
   string for a queued whole-checklist *submission*; `workflows.html` now renders it for a single
   unsent field answer. Two states, one string, same screen. This card owns both files: name them
   apart.
- Footprint: `backend/internal/workflow`, a migration, `workflows.html`, `sync.js`.
- **Estimate ~2h30m–3h30m** (basis: 07-26 Card B `sync-jwt-bridge-endpoint`, Go endpoint + SQL —
  82m impl + 10m G6 + 11m repair ≈ 1h45m — **plus** a front-end leg and a full Playwright run, which
  on 07-27's front-end card cost another hour of repair).
- **Riskiest card tonight — PARK note:** a migration that needs to de-duplicate existing
  `submission_fail_notes` rows before the unique index can be created is a data decision, not a
  schema one. If prod-shaped duplicates exist, **park** rather than choose a dedup rule unattended.
