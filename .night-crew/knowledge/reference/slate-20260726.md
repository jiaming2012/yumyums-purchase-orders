### Planner decision: RxDB reaches the browser as a committed, vendored ESM bundle

Not previously asked and not in any fork document — the feasibility verdict assumes it away
(`sync-rxdb-feasibility-spike.md:505-508` says only *"budget a real browser spike inside that
card"*). It is load-bearing and it had to be settled before the schema card could be sized, so it
is settled here as an Engineer/PjM call, stated rather than asked. **Operator may override at
sign-off.**

The constraint it runs into: CLAUDE.md states **"Static only: No build step, no framework"**, and
the repo's one external dependency (SortableJS) is a `<script src="https://unpkg.com/…">` CDN tag
(`workflows.html:172`). There is **no bundler in the repo** and `package.json` has **zero runtime
dependencies**.

Three candidates, and why the third wins:

1. **CDN ESM import** (`https://esm.sh/rxdb@17.4.0`) — matches the SortableJS precedent, zero new
   machinery. **Rejected:** this is a food-truck PWA whose whole reason for adopting RxDB is
   offline correctness. Putting the offline data engine behind a CDN the truck cannot reach with
   no signal inverts the point, and Workbox precaches **local content-hashed files** — a CDN URL
   would need runtime caching, i.e. a *second* offline story, which Engineering KR3 explicitly
   forbids ("exactly 1 documented owner per offline data class").
2. **A real build step** (esbuild wired into `task sw` / the Dockerfile) — cleanest long-term.
   **Rejected for tonight:** it breaks a stated project constraint and rewrites the deploy path.
   That is an operator decision, not a card's.
3. ✅ **Vendored pre-built bundle.** A committed script generates `vendor/rxdb.bundle.js` (+
   `@supabase/supabase-js`) via **`npx esbuild@<pinned>`**, the output is **committed**, loaded
   with a plain `<script type="module" src="vendor/…">`, and precached by Workbox like every other
   local asset. **No build step in the deploy path** — the constraint holds. Regeneration is a
   deliberate, hand-run act on upgrade, which is also where FORK 4's "smoke test that fails loudly
   on upgrade" naturally attaches.
   **Deliberately NOT added to `package.json`/`package-lock.json`** — `npx esbuild@<pinned>` keeps
   the root Playwright environment byte-untouched, which is what makes concurrent dispatch safe
   tonight.

**Card C proves this by execution or returns NO-GO with a named alternative.** A NO-GO is a
completed card, not a failed one.

   NULL, and a non-UUID `sub` raises `invalid input syntax for type uuid`. Verified at triage
   against the live catalog. **Write policies against the plural GUC / a claim the stack actually
   delivers, and prove it discriminating.**

expired token · missing `sub` · wrong signature · **token replay after grant revocation** · forged

nothing** (W1's rule, and a `service_role` BYPASSRLS control is what rules out "the table was

## Execution notes

- **Single session, Wave-0-then-concurrent:** A alone → merge → then dispatch C and B concurrently,
  at most one in-flight card per track. Orchestrator alone merges, C before B (C's `build-sw.js`
  change is the one with reach).
- **Single session, fully serial:** A → C → B, in that order.
- **Two-session split:** session 1 = A + C (the frontend/verdict half, ~170–390 m); session 2 = B
  (fully disjoint, backend-only — it shares no file with either).
- **`export PATH="/usr/local/go/bin:$PATH"` before any Playwright or Go leg.** The non-interactive
  shell does not carry Go; Playwright's `webServer` dies with `go: not found` / exit 127, which
  **looks like a test failure and is not**. Cost two aborted legs on 20260725. **This box's PATH
  contains spaces** (`/mnt/c/Program Files/…`) — always quote; bare `env PATH=$PATH …` splits.
- **`-p 1` is load-bearing** for the Go suite — without it `backend/internal/workflow` reds with
  `checklist_templates_created_by_fkey` violations (cross-package `users` truncation on a shared
  `hq_test_go`).
- **`CI=1` on every suite/G6 leg** — forces `reuseExistingServer:false`. The `:8199` foreign-server
  latch has cost wall-clock on two separate runs.
- **Separate `TEST_PORT`/`TEST_DB_NAME` per leg** (8199/8299/8399/…) — zero collisions across four
  legs on 20260725 with this discipline.
- **Never `git stash`** in a worktree — worktrees share `refs/stash`; one `stash pop` once pulled a
  concurrent card's WIP into the wrong tree.
- **Never background a suite run naively** — `$!` after `nohup … &` yields a wrapper pid that exits
  immediately, and `tail --pid` on it returns instantly and **looks like a finished run**. Find the
  real `node`/`go` pid with `pgrep -af`.
- **`sw.js` is generated.** Never hand-resolve a conflict in it — re-run `node build-sw.js`.
- **The box is never idle** (~13 unrelated containers). Report measured 1-min load with every suite
  result; a green here bounds the *loaded-ish* condition, not a quiet one.
- **The spike Supabase stack is currently RUNNING** (`docker compose -p spike-supabase -f
  docker-compose.supabase.yml`). Do not tear it down — card B needs it, and teardown is an
  explicit, deliberately unexecuted runbook step.
